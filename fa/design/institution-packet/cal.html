DiTA — دستیار جدول زمانی توزیع‌شده

تقویم

یک تقویم، بازه‌های زمانی قابل استفاده برای یک مؤسسه یا سایر موجودیت‌های زمان‌بندی را تعریف می‌کند. تقویم شامل مجموعه‌ای از ورودی‌های دسترسی زمانی (availability) است که مشخص می‌کنند یک بازه چه زمانی فعال، غیرقابل‌استفاده، ترجیحی یا نامطلوب است.

ساختار

یک تقویم شامل مجموعه‌ای به نام avails است.

Calendar

فیلدتوضیحات
availsفهرستی از ورودی‌های دسترسی زمانی. هر ورودی یک بازه زمانی و نحوه رفتار آن در زمان‌بندی را مشخص می‌کند.

مثال:

avails:
  - type: Weekly
    start: 2026-01-28T00:00:00+10:00
    end: 2026-12-12T23:59:59+10:00
    ...

انواع Availability

هر ورودی availability دارای یک type است که مشخص می‌کند تعریف زمانی آن چگونه تفسیر شود.

انواع پشتیبانی‌شده عبارت‌اند از:

نوعتوضیحات
Yearlyیک الگوی زمانی تکرارشونده را بر اساس ماه و روز سال تعریف می‌کند.
Monthlyیک الگوی زمانی تکرارشونده را بر اساس روز ماه تعریف می‌کند.
Weeklyیک الگوی زمانی تکرارشونده را بر اساس روزهای هفته تعریف می‌کند.
Dailyیک الگوی زمانی تکرارشونده را بر اساس ساعت روز تعریف می‌کند.
Basicیک بازه زمانی مستقیم را بدون الگوی تقویمی تکرارشونده تعریف می‌کند.
Holidayیک بازه زمانی مرتبط با تعطیلات رسمی یک کشور یا منطقه مشخص را تعریف می‌کند.

انواع Yearly، Monthly، Weekly و Daily می‌توانند شامل time cellهای تو‌در‌تو باشند و به این ترتیب به تقویم اجازه می‌دهند یک بازه زمانی را به‌صورت تدریجی محدودتر و دقیق‌تر تعریف کند.

بازه زمانی مشترک

انواع availability تکرارشونده دارای start و end هستند که دوره کلی اعمال شدن availability را مشخص می‌کنند.

برای مثال:

- type: Weekly
  start: 2026-01-28T00:00:00+10:00
  end: 2026-12-12T23:59:59+10:00

مقادیر start و end از قالب تاریخ-زمان ISO 8601 استفاده می‌کنند.

درون این بازه، time cellهای تو‌در‌تو بخش‌های تکرارشونده برنامه را تعریف می‌کنند.

Time Cellها

Time cellها عناصر تو‌در‌تویی هستند که برای توصیف تدریجی یک برنامه تکرارشونده استفاده می‌شوند.

یک time cell دارای type است و می‌تواند شامل موارد زیر باشد:

  • start
  • end
  • time_cells

انواع time cellهای قابل استفاده به محدوده زمانی والد آن بستگی دارند.

Weekly

یک availability از نوع Weekly یک برنامه تکرارشونده را درون یک بازه تاریخ-زمان مشخص تعریف می‌کند.

time cellهای تو‌در‌توی آن می‌توانند از انواع زیر باشند:

  • Daily
  • Basic

مثال:

- type: Weekly
  start: 2026-01-28T00:00:00+10:00
  end: 2026-12-12T23:59:59+10:00
  time_cells:
    - type: Daily
      ...
    - type: Basic
      ...

Daily

یک time cell از نوع Daily یک بازه از روزها را مشخص می‌کند و شامل ورودی‌های مبتنی بر زمان است.

start و end آن مرزهای بازه روزها را مشخص می‌کنند. هر مرز شامل موارد زیر است:

  • day: روز هفته
  • time: زمان در آن روز

برای مثال:

- type: Daily
  start:
    day: Mon
    time: 00:00:00
  end:
    day: Fri
    time: 23:59:59
  time_cells:
    ...

مقادیر قابل استفاده برای روز هفته عبارت‌اند از:

مقدارروز
Monدوشنبه
Tueسه‌شنبه
Wedچهارشنبه
Thuپنج‌شنبه
Friجمعه
Satشنبه
Sunیکشنبه

یک time cell از نوع Daily می‌تواند شامل time cellهای Basic باشد.

Basic

یک time cell از نوع Basic یک بازه زمانی مشخص و مستقیم را نشان می‌دهد.

این نوع شامل موارد زیر است:

فیلدتوضیحات
startشروع بازه زمانی.
endپایان بازه زمانی.
rulesفهرستی از قوانین مرتبط با بازه زمانی.
statusوضعیت availability بازه زمانی.
div_capمشخص می‌کند بازه زمانی چگونه می‌تواند برای زمان‌بندی تقسیم شود. مقدار 0 یعنی بازه انعطاف‌پذیر است و یک فعالیت زمان‌بندی‌شده می‌تواند هر بخشی از آن را اشغال کند. مقدار 1 یعنی کل بازه تنها ظرفیت یک فعالیت را فراهم می‌کند. مقادیر بزرگ‌تر از 1 امکان تقسیم بازه برای چند تخصیص زمان‌بندی را فراهم می‌کنند.

فیلد div_cap نحوه تقسیم ظرفیت بازه زمانی را کنترل می‌کند. این فیلد مدت‌زمان فعالیت‌های زمان‌بندی‌شده را تعیین نمی‌کند.

برای مثال، یک بازه انعطاف‌پذیر را می‌توان به‌صورت زیر تعریف کرد:

- type: Basic
  start: 07:30:00
  end: 13:00:00
  rules: []
  status: Available
  div_cap: 0

با div_cap: 0، یک فعالیت می‌تواند با توجه به سایر محدودیت‌های زمان‌بندی، در هر زمانی بین 07:30 تا 13:00 زمان‌بندی شود. این بازه الزامی نیست که به‌عنوان یک slot زمانی ثابت و واحد در نظر گرفته شود.

یک بازه با یک ظرفیت ثابت و واحد را می‌توان به‌صورت زیر تعریف کرد:

- type: Basic
  start: 08:30:00
  end: 09:20:00
  rules: []
  status: Available
  div_cap: 1

با div_cap: 1، کل بازه یک ظرفیت زمان‌بندی را تشکیل می‌دهد و نمی‌توان از آن برای چند فعالیت هم‌زمان استفاده کرد.

یک بازه قابل تقسیم را می‌توان با مقداری بزرگ‌تر از 1 تعریف کرد:

- type: Basic
  start: 08:30:00
  end: 10:10:00
  rules: []
  status: Available
  div_cap: 2

با div_cap: 2، این بازه دو واحد ظرفیت زمان‌بندی فراهم می‌کند. بسته به نیازهای زمان‌بندی، این ظرفیت‌ها می‌توانند برای قرار دادن چند فعالیت درون این بازه استفاده شوند؛ برای مثال با تقسیم بازه به بخش‌های جداگانه یا استفاده از آن برای فعالیت‌هایی که یک هفته در میان برگزار می‌شوند.

یک time cell از نوع Basic شامل time cell تو‌در‌توی دیگری نیست.

وضعیت Availability

یک time cell از نوع Basic دارای status است که مشخص می‌کند scheduler باید با آن بازه زمانی چگونه رفتار کند.

وضعیتتوضیحات
Availableزمان می‌تواند برای زمان‌بندی استفاده شود.
Unavailableزمان نمی‌تواند برای زمان‌بندی استفاده شود.
Preferredاین زمان برای زمان‌بندی ترجیح داده می‌شود.
Undesiredبه‌طور کلی بهتر است از این زمان اجتناب شود، اما در صورت نیاز می‌توان از آن استفاده کرد.

برای مثال:

- type: Basic
  start: 09:20:00
  end: 10:10:00
  rules: []
  status: Available
  div_cap: 1

می‌توان از یک وضعیت دیگر برای بیان ترجیح یا محدودیت استفاده کرد، بدون اینکه بازه زمانی از تقویم حذف شود:

- type: Basic
  start:
    day: Fri
    time: 09:20:00
  end:
    day: Fri
    time: 10:10:00
  rules: []
  status: Undesired
  div_cap: 1

تعطیلات

یک availability از نوع Holiday یک دوره مرتبط با تعطیلات را نشان می‌دهد.

برخلاف انواع time cellهای تکرارشونده، یک ورودی Holiday مستقیماً یک بازه تاریخ-زمان را تعریف می‌کند و کشور یا منطقه‌ای را که تقویم تعطیلات آن مورد استفاده قرار گرفته است مشخص می‌کند.

این نوع شامل موارد زیر است:

فیلدتوضیحات
startشروع دوره مرتبط با تعطیلات.
endپایان دوره مرتبط با تعطیلات.
countryشناسه کشور یا منطقه مورد استفاده برای تعریف تعطیلات.
statusوضعیت availability اعمال‌شده بر دوره تعطیلات.

مثال:

- type: Holiday
  start: 2026-01-28T00:00:00+10:00
  end: 2026-12-12T23:59:59+10:00
  country: "au-qld"
  status: Unavailable

برای مثال، قرار دادن Unavailable به‌عنوان وضعیت می‌تواند از زمان‌بندی در طول تعطیلات رسمی مربوط به منطقه مشخص‌شده جلوگیری کند.

قوانین تو‌در‌تویی

سلسله‌مراتب تعاریف زمانی این امکان را فراهم می‌کند که یک بازه گسترده به‌صورت تدریجی دقیق‌تر و محدودتر شود.

یک ساختار معمول به شکل زیر است:

Calendar
└── Availability
    └── Weekly
        ├── Daily
        │   └── Basic
        └── Basic

برای مثال، ساختار زیر:

- type: Weekly
  start: 2026-01-28T00:00:00+10:00
  end: 2026-12-12T23:59:59+10:00
  time_cells:
    - type: Daily
      start:
        day: Mon
        time: 00:00:00
      end:
        day: Fri
        time: 23:59:59
      time_cells:
        - type: Basic
          start: 08:30:00
          end: 09:20:00
          rules: []
          status: Available
          div_cap: 1

را می‌توان به این صورت تفسیر کرد:

  1. availability در بازه تاریخ-زمان مشخص‌شده اعمال می‌شود.
  2. درون این بازه، از دوشنبه تا جمعه اعمال می‌شود.
  3. درون این روزها، بازه زمانی مشخص‌شده از 08:30 تا 09:20 در دسترس است.
  4. این بازه یک ظرفیت زمان‌بندی فراهم می‌کند، زیرا div_cap برابر 1 است.

این ساختار سلسله‌مراتبی به تقویم‌ها اجازه می‌دهد هم بازه‌های گسترده و تکرارشونده و هم بازه‌های زمانی مشخص و دقیق برای زمان‌بندی را نمایش دهند.

مثال کامل

مثال زیر یک تقویم مدرسه برای سال 2026 را تعریف می‌کند. این تقویم شامل یک برنامه هفتگی از دوشنبه تا جمعه، دوره‌های کلاسی مجزا، زمان‌های استراحت حذف‌شده، یک بازه زمانی جداگانه با وضعیت نامطلوب و یک دوره تعطیلات برای کوئینزلند است.

avails:
  - type: Weekly
    start: 2026-01-28T00:00:00+10:00
    end: 2026-12-12T23:59:59+10:00
    time_cells:
      - type: Daily
        start:
          day: Mon
          time: 00:00:00
        end:
          day: Fri
          time: 23:59:59
        time_cells:
          # Period 1: 08:30 - 09:20
          - type: Basic
            start: 08:30:00
            end: 09:20:00
            rules: []
            status: Available
            div_cap: 1

          # Period 2: 09:20 - 10:10
          - type: Basic
            start: 09:20:00
            end: 10:10:00
            rules: []
            status: Available
            div_cap: 1

          # Break 1 (Morning Tea): 10:10 - 10:40 (Excluded)

          # Period 3: 10:40 - 11:30
          - type: Basic
            start: 10:40:00
            end: 11:30:00
            rules: []
            status: Available
            div_cap: 1

          # Consolidation: 12:20 - 13:00
          - type: Basic
            start: 12:20:00
            end: 13:00:00
            rules: []
            status: Available
            div_cap: 1

          # Break 2 (Lunch): 13:00 - 13:30 (Excluded)

          # Period 5: 13:30 - 14:20
          - type: Basic
            start: 13:30:00
            end: 14:20:00
            rules: []
            status: Available
            div_cap: 1

          # Period 6: 14:20 - 15:10
          - type: Basic
            start: 14:20:00
            end: 15:10:00
            rules: []
            status: Available
            div_cap: 1

      - type: Basic
        start:
          day: Fri
          time: 09:20:00
        end:
          day: Fri
          time: 10:10:00
        rules: []
        status: Undesired
        div_cap: 1

  - type: Holiday
    start: 2026-01-28T00:00:00+10:00
    end: 2026-12-12T23:59:59+10:00
    country: "au-qld"
    status: Unavailable
