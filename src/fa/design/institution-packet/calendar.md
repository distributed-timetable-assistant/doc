# تقویم

یک تقویم، دسترس‌پذیری زمانی یک مؤسسه یا سایر موجودیت‌های زمان‌بندی را تعریف می‌کند. تقویم شامل مجموعه‌ای از ورودی‌های دسترس‌پذیری است که مشخص می‌کنند یک بازهٔ زمانی چه زمانی فعال، غیرقابل‌استفاده، ترجیحی یا نامطلوب است.

## ساختار

یک تقویم شامل مجموعه‌ای به نام `availabilities` است.

### Calendar

| فیلد             | توضیحات                                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------------ |
| `availabilities` | فهرستی از ورودی‌های دسترس‌پذیری. هر ورودی یک بازهٔ زمانی و نحوهٔ رفتار آن در زمان‌بندی را مشخص می‌کند. |

مثال:

```yaml
availabilities:
  - type: Weekly
    start: 2026-01-28T00:00:00+10:00
    end: 2026-12-12T23:59:59+10:00
    ...
```

## انواع دسترس‌پذیری

هر ورودی دسترس‌پذیری دارای یک `type` است که نحوهٔ تفسیر تعریف زمانی آن را مشخص می‌کند.

انواع پشتیبانی‌شده عبارت‌اند از:

| نوع       | توضیحات                                                                      |
| --------- | ---------------------------------------------------------------------------- |
| `Yearly`  | یک الگوی زمانی تکرارشونده را بر اساس ماه و روز سال تعریف می‌کند.             |
| `Monthly` | یک الگوی زمانی تکرارشونده را بر اساس روز ماه تعریف می‌کند.                   |
| `Weekly`  | یک الگوی زمانی تکرارشونده را بر اساس روزهای هفته تعریف می‌کند.               |
| `Daily`   | یک الگوی زمانی تکرارشونده را بر اساس زمان در طول روز تعریف می‌کند.           |
| `Basic`   | یک بازهٔ زمانی مستقیم و بدون الگوی تکرارشوندهٔ تقویمی تعریف می‌کند.          |
| `Holiday` | یک بازهٔ زمانی مرتبط با تعطیلات رسمی یک کشور یا منطقهٔ مشخص را تعریف می‌کند. |

انواع `Yearly`، `Monthly`، `Weekly` و `Daily` می‌توانند شامل سلول‌های زمانی تو‌در‌تو باشند و به این ترتیب امکان محدود کردن تدریجی یک بازهٔ زمانی را فراهم می‌کنند.

## بازهٔ زمانی مشترک

انواع دسترس‌پذیری تکرارشونده دارای `start` و `end` هستند که بازهٔ کلی زمانی اعمال دسترس‌پذیری را مشخص می‌کنند.

برای مثال:

```yaml
- type: Weekly
  start: 2026-01-28T00:00:00+10:00
  end: 2026-12-12T23:59:59+10:00
```

مقادیر `start` و `end` از قالب تاریخ-زمان ISO 8601 استفاده می‌کنند.

در داخل این بازه، سلول‌های زمانی تو‌در‌تو بخش‌های تکرارشوندهٔ برنامه را تعریف می‌کنند.

## سلول‌های زمانی

سلول‌های زمانی عناصر تو‌در‌تویی هستند که برای توصیف تدریجی یک برنامهٔ تکرارشونده استفاده می‌شوند.

یک سلول زمانی دارای `type` است و ممکن است شامل موارد زیر باشد:

* `start`
* `end`
* `time_cells`

انواع تو‌در‌توی قابل استفاده به محدودهٔ زمانی والد بستگی دارند.

### Weekly

یک `Weekly`، برنامه‌ای تکرارشونده را درون یک بازهٔ تاریخ-زمان مشخص توصیف می‌کند.

سلول‌های زمانی تو‌در‌توی آن می‌توانند از انواع زیر باشند:

* `Daily`
* `Basic`

مثال:

```yaml
- type: Weekly
  start: 2026-01-28T00:00:00+10:00
  end: 2026-12-12T23:59:59+10:00
  time_cells:
    - type: Daily
      ...
    - type: Basic
      ...
```

### Daily

یک سلول زمانی `Daily` بازه‌ای از روزها را توصیف می‌کند و شامل ورودی‌های مبتنی بر زمان است.

`start` و `end` آن، مرزهای بازهٔ روزها را مشخص می‌کنند. هر مرز شامل موارد زیر است:

* `day`: روز هفته.
* `time`: زمان در آن روز.

برای مثال:

```yaml
- type: Daily
  start:
    day: Mon
    time: 00:00:00
  end:
    day: Fri
    time: 23:59:59
  time_cells:
    ...
```

مقادیر پشتیبانی‌شده برای روز عبارت‌اند از:

| مقدار | روز      |
| ----- | -------- |
| `Mon` | دوشنبه   |
| `Tue` | سه‌شنبه  |
| `Wed` | چهارشنبه |
| `Thu` | پنج‌شنبه |
| `Fri` | جمعه     |
| `Sat` | شنبه     |
| `Sun` | یکشنبه   |

یک سلول زمانی `Daily` می‌تواند شامل سلول‌های زمانی `Basic` باشد.

### Basic

یک سلول زمانی `Basic` یک بازهٔ زمانی مشخص را نشان می‌دهد.

شامل موارد زیر است:

| فیلد     | توضیحات                                |
| -------- | -------------------------------------- |
| `start`  | شروع بازهٔ زمانی.                      |
| `end`    | پایان بازهٔ زمانی.                     |
| `rules`  | فهرستی از قوانین مرتبط با بازهٔ زمانی. |
| `status` | وضعیت دسترس‌پذیری بازهٔ زمانی.         |

مثال:

```yaml
- type: Basic
  start: 08:30:00
  end: 09:20:00
  rules: []
  status: Available
```

یک سلول زمانی `Basic` شامل سلول زمانی تو‌در‌توی دیگری نیست.

## وضعیت دسترس‌پذیری

یک سلول زمانی `Basic` دارای `status` است که مشخص می‌کند زمان موردنظر باید توسط زمان‌بند چگونه در نظر گرفته شود.

| وضعیت         | توضیحات                                                                          |
| ------------- | -------------------------------------------------------------------------------- |
| `Available`   | این زمان می‌تواند برای زمان‌بندی استفاده شود.                                    |
| `Unavailable` | این زمان نمی‌تواند برای زمان‌بندی استفاده شود.                                   |
| `Preferred`   | این زمان برای زمان‌بندی ترجیح داده می‌شود.                                       |
| `Undesired`   | معمولاً باید از این زمان اجتناب شود، اما در صورت نیاز می‌توان از آن استفاده کرد. |

برای مثال:

```yaml
- type: Basic
  start: 09:20:00
  end: 10:10:00
  rules: []
  status: Available
```

می‌توان از وضعیت دیگری برای بیان یک ترجیح یا محدودیت استفاده کرد، بدون اینکه بازهٔ زمانی از تقویم حذف شود:

```yaml
- type: Basic
  start:
    day: Fri
    time: 09:20:00
  end:
    day: Fri
    time: 10:10:00
  rules: []
  status: Undesired
```

## تعطیلات

یک دسترس‌پذیری از نوع `Holiday` یک بازهٔ زمانی مرتبط با تعطیلات را نشان می‌دهد.

برخلاف انواع سلول زمانی تکرارشونده، یک ورودی `Holiday` مستقیماً یک بازهٔ تاریخ-زمان را تعریف می‌کند و کشور یا منطقه‌ای را که تقویم تعطیلات آن موردنظر است مشخص می‌کند.

این ورودی شامل موارد زیر است:

| فیلد      | توضیحات                                                    |
| --------- | ---------------------------------------------------------- |
| `start`   | شروع بازهٔ زمانی مرتبط با تعطیلات.                         |
| `end`     | پایان بازهٔ زمانی مرتبط با تعطیلات.                        |
| `country` | شناسهٔ کشور یا منطقه که برای تعریف تعطیلات استفاده می‌شود. |
| `status`  | وضعیت دسترس‌پذیری اعمال‌شده بر بازهٔ تعطیلات.              |

مثال:

```yaml
- type: Holiday
  start: 2026-01-28T00:00:00+10:00
  end: 2026-12-12T23:59:59+10:00
  country: "au-qld"
  status: Unavailable
```

برای مثال، قرار دادن وضعیت روی `Unavailable` می‌تواند از زمان‌بندی در طول تعطیلات رسمی مربوط به منطقهٔ مشخص‌شده جلوگیری کند.

## قوانین تو‌در‌تویی

سلسله‌مراتب تعاریف زمانی این امکان را فراهم می‌کند که یک بازهٔ کلی به‌صورت تدریجی محدود و دقیق‌تر شود.

یک ساختار معمول به شکل زیر است:

```text
Calendar
└── Availability
    └── Weekly
        ├── Daily
        │   └── Basic
        └── Basic
```

برای مثال، ساختار زیر:

```yaml
- type: Weekly
  start: 2026-01-28T00:00:00+10:00
  end: 2026-12-12T23:59:59+10:00
  time_cells:
    - type: Daily
      start:
        day: Mon
        time: 00:00:00
      end:
        day: Fri
        time: 23:59:59
      time_cells:
        - type: Basic
          start: 08:30:00
          end: 09:20:00
          rules: []
          status: Available
```

را می‌توان به شکل زیر تفسیر کرد:

1. این دسترس‌پذیری در بازهٔ تاریخ-زمان مشخص‌شده اعمال می‌شود.
2. درون این بازه، از دوشنبه تا جمعه اعمال می‌شود.
3. درون این روزها، بازهٔ زمانی مشخص‌شده از `08:30` تا `09:20` در دسترس است.

این ساختار سلسله‌مراتبی به تقویم‌ها اجازه می‌دهد هم بازه‌های تکرارشوندهٔ گسترده و هم بازه‌های زمانی مشخص برای زمان‌بندی را نمایش دهند.

## مثال کامل

مثال زیر یک تقویم مدرسه برای سال ۲۰۲۶ را تعریف می‌کند. این تقویم شامل یک برنامهٔ هفتگی از دوشنبه تا جمعه، زمان‌های جداگانهٔ کلاس‌ها، وقفه‌های حذف‌شده، یک بازهٔ جداگانهٔ نامطلوب و یک بازهٔ تعطیلات برای کوئینزلند است.

```yaml
availabilities:
  - type: Weekly
    start: 2026-01-28T00:00:00+10:00
    end: 2026-12-12T23:59:59+10:00
    time_cells:
      - type: Daily
        start:
          day: Mon
          time: 00:00:00
        end:
          day: Fri
          time: 23:59:59
        time_cells:
          # Period 1: 08:30 - 09:20
          - type: Basic
            start: 08:30:00
            end: 09:20:00
            rules: []
            status: Available

          # Period 2: 09:20 - 10:10
          - type: Basic
            start: 09:20:00
            end: 10:10:00
            rules: []
            status: Available

          # Break 1 (Morning Tea): 10:10 - 10:40 (Excluded)

          # Period 3: 10:40 - 11:30
          - type: Basic
            start: 10:40:00
            end: 11:30:00
            rules: []
            status: Available

          # Consolidation: 12:20 - 13:00
          - type: Basic
            start: 12:20:00
            end: 13:00:00
            rules: []
            status: Available

          # Break 2 (Lunch): 13:00 - 13:30 (Excluded)

          # Period 5: 13:30 - 14:20
          - type: Basic
            start: 13:30:00
            end: 14:20:00
            rules: []
            status: Available

          # Period 6: 14:20 - 15:10
          - type: Basic
            start: 14:20:00
            end: 15:10:00
            rules: []
            status: Available

      - type: Basic
        start:
          day: Fri
          time: 09:20:00
        end:
          day: Fri
          time: 10:10:00
        rules: []
        status: Undesired

  - type: Holiday
    start: 2026-01-28T00:00:00+10:00
    end: 2026-12-12T23:59:59+10:00
    country: "au-qld"
    status: Unavailable
```

یک نکتهٔ مهم در ترجمه: در این سند، `availability` را به **دسترس‌پذیری** و `time cell` را به **سلول زمانی** ترجمه کردم و نام فیلدها و enumها را دست‌نخورده نگه داشتم تا برای مستندات فنی DiTA قابل استفاده باشند.
